Arquitetura MVT do Django

O Django organiza as aplicações web segundo a arquitetura MVT, que significa Model, View e Template. Esta arquitetura separa as responsabilidades da aplicação, tornando o código mais organizado, mais fácil de compreender e mais simples de manter.

Componentes principais

Model: representa os dados da aplicação. No Django, os modelos são classes Python que definem entidades, campos e relações. A partir destes modelos, o Django consegue comunicar com a base de dados.

View: recebe o pedido do utilizador, executa a lógica necessária e devolve uma resposta. Pode consultar modelos, preparar dados e escolher o template que será apresentado.

Template: define a apresentação visual da página. É aqui que os dados enviados pela view são mostrados ao utilizador em HTML.

URL Dispatcher: é o sistema de rotas do Django. Analisa o endereço pedido pelo utilizador e encaminha esse pedido para a view correta.

Browser/utilizador: representa quem acede à aplicação. O browser envia pedidos HTTP e apresenta as páginas HTML recebidas como resposta.

Base de dados: guarda a informação persistente da aplicação, como projetos, tecnologias, unidades curriculares e outros dados definidos nos modelos.

Fluxo de informação

  1. O utilizador faz um pedido através do browser.
  2. O URL Dispatcher analisa o URL e chama a view correspondente.
  3. A view executa a lógica necessária para responder ao pedido.
  4. Quando precisa de dados, a view comunica com o Model.
  5. O Model consulta ou altera informação na base de dados.
  6. A view envia os dados preparados para o Template.
  7. O Template gera a página HTML final.
  8. O browser recebe essa página e apresenta-a ao utilizador.

Modelação

A modelação da aplicação foi definida no ficheiro portfolio/models.py. Este ficheiro contém as classes que representam as principais entidades do portefólio e as relações entre elas. Cada classe Django corresponde, em regra, a uma tabela na base de dados.

Entidades principais

Licenciatura: representa um curso, com campos como nome, sigla, descrição, objetivos, total de ECTS, duração, URL oficial e departamento.

Docente: representa um professor. Guarda o nome, a URL da página oficial e, opcionalmente, uma fotografia.

UnidadeCurricular: representa uma disciplina. Inclui campos como nome, sigla, descrição, ECTS, imagem, ano curricular, semestre, objetivos, conteúdos, bibliografia e apresentação.

Tecnologia: representa uma tecnologia usada ou estudada no portefólio. Tem nome, descrição, tipo, logo, URL oficial e nível de interesse. O tipo é definido através da entidade TipoTecnologia.

TipoTecnologia: representa a categoria de uma tecnologia, como Frontend, Backend, Base de Dados, Storage ou Outros. Esta separação evita repetir texto livre e permite agrupar tecnologias de forma mais consistente.

Projeto: representa um projeto desenvolvido. Guarda título, descrição, âmbito, conceitos aplicados, links, imagem, vídeo, ano e a unidade curricular associada, quando existir.

TFC: representa um Trabalho Final de Curso. Inclui título, resumo, ano, links, nível de interesse, parceiro, palavras-chave e áreas.

Competencia: representa uma competência técnica ou pessoal, com nome, categoria, descrição e nível.

Formacao: representa formação académica, certificação ou workshop, com título, instituição, datas, certificado e tipo.

ExperienciaProfissional: representa uma experiência de trabalho, com empresa, cargo, tipo, descrição, datas, tecnologias e competências associadas.

MakingOf: guarda registos do processo de desenvolvimento, incluindo descrição, decisões, erros e correções, imagem de apoio e uso de IA.

Relações entre entidades

A entidade UnidadeCurricular tem uma relação de muitos para muitos com Licenciatura, porque uma disciplina pode pertencer a mais do que uma licenciatura e uma licenciatura tem várias disciplinas.

A entidade UnidadeCurricular também se relaciona com Docente através de uma relação de muitos para muitos, permitindo representar disciplinas lecionadas por vários docentes.

A entidade Projeto pode estar associada a uma UnidadeCurricular através de uma chave estrangeira. Esta relação indica a disciplina onde o projeto foi desenvolvido.

A entidade Projeto tem uma relação de muitos para muitos com Tecnologia, porque um projeto pode usar várias tecnologias e a mesma tecnologia pode ser usada em vários projetos.

A entidade Tecnologia pertence a um TipoTecnologia. Esta relação permite classificar cada tecnologia e preparar a página para apresentar tecnologias agrupadas por tipo.

A entidade TFC relaciona-se com Docente através dos orientadores, com Licenciatura através de uma chave estrangeira e com Tecnologia através de uma relação de muitos para muitos.

A entidade Competencia pode ser associada a projetos e formações. A entidade ExperienciaProfissional também se relaciona com tecnologias e competências, permitindo ligar experiência, ferramentas utilizadas e capacidades desenvolvidas.

Importância das tecnologias no projeto

O Django permite construir a aplicação no lado do servidor, organizar rotas, views, modelos e templates. A sua principal vantagem é acelerar o desenvolvimento com uma estrutura já preparada; como ponto menos positivo, exige compreender bem a organização do framework.

O HTML define a estrutura das páginas e o CSS controla a apresentação visual. São tecnologias essenciais para construir a interface, embora exijam atenção à organização e à responsividade.

O Git e o GitHub ajudam a controlar versões, manter histórico de alterações e guardar o projeto remotamente. A principal vantagem é a segurança e organização do trabalho; a dificuldade inicial está em compreender bem commits, branches e merges.

A base de dados, neste projeto SQLite, guarda os dados persistentes da aplicação. É simples de usar em desenvolvimento, embora em projetos maiores possa fazer sentido usar uma solução mais robusta, como PostgreSQL.

Estrutura das páginas

A aplicação está organizada em várias páginas ligadas através do menu de navegação principal do portefólio. Esta estrutura permite separar a informação por temas, tornando a consulta mais clara e facilitando a manutenção futura.

Navegação principal

A página inicial do portefólio funciona como ponto de entrada para as restantes áreas. A partir do menu, o utilizador pode aceder às páginas de consulta, às páginas técnicas e aos registos do processo de desenvolvimento.

  • Início: apresenta as principais áreas disponíveis no portefólio.
  • Sobre esta Aplicação: reúne a documentação técnica da aplicação, incluindo arquitetura, modelação, tecnologias e estrutura.
  • Licenciaturas: lista os cursos registados e a sua informação principal.
  • Docentes: apresenta os docentes e as unidades curriculares associadas.
  • Disciplinas: mostra as unidades curriculares e a sua relação com cursos e docentes.
  • Tecnologias: lista tecnologias usadas, estudadas ou associadas a projetos.
  • Projetos: apresenta projetos desenvolvidos e as tecnologias utilizadas em cada um.
  • TFCs: mostra Trabalhos Finais de Curso e informação associada.
  • Competências: organiza competências técnicas ou pessoais e liga-as a projetos e formações.
  • Formações: apresenta formação académica, certificações ou workshops.
  • Experiências: mostra experiências profissionais, tecnologias usadas e competências relacionadas.
  • Making of: guarda registos do processo de desenvolvimento da aplicação.

Relação entre páginas

As páginas de consulta estão ligadas pelos dados definidos nos modelos. Por exemplo, um projeto pode estar associado a tecnologias, uma unidade curricular pode estar ligada a docentes e licenciaturas, e uma experiência profissional pode estar relacionada com tecnologias e competências.

Esta organização permite que a aplicação cresça sem concentrar toda a informação numa única página. No futuro, podem ser adicionadas novas páginas ou subpáginas mantendo o mesmo padrão: rota em urls.py, view em views.py e template próprio com herança de base.html.

Utilização do GitHub no desenvolvimento

O GitHub foi usado em conjunto com o Git para guardar versões do projeto ao longo do tempo. Cada alteração importante pode ser registada através de commits, permitindo acompanhar a evolução da aplicação e compreender que decisões foram tomadas em cada fase.

Esta forma de trabalho é útil porque permite controlar versões, manter um histórico de alterações, facilitar colaboração, criar um backup remoto e organizar melhor os ficheiros do projeto.

Vantagens

  • Controlo de versões: permite guardar estados sucessivos do projeto e recuperar alterações anteriores se necessário.
  • Histórico de alterações: facilita perceber quando e porque foi feita determinada alteração.
  • Colaboração: permite que várias pessoas trabalhem no mesmo projeto de forma mais organizada.
  • Backup remoto: mantém uma cópia do projeto fora do computador local.
  • Organização do projeto: centraliza o código, a documentação e a evolução do trabalho.
